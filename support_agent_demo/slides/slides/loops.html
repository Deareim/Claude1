Loops

A branch goes forward. A loop goes back and tries again.

1 · Ask and retry

In the demo

Missing information? Ask, then try again.

No order found → ask the customer for the number → search again.

2 · Check my own work

Could add

Not good enough? Review, then rewrite.

The reply breaks policy or sounds rude → the agent rewrites it before sending.

3 · Human feedback

Could add

Person says no? Rethink with their comment.

Manager rejects: "offer a voucher instead" → Resolution Agent decides again.

4 · Tool retry

Could add

A tool failed? Try again, or try another way.

Database times out → wait and retry, or search by email instead.

Every loop needs a stop rule, e.g. "max 3 tries, then hand over to a person", so the agent never goes round forever.

Use this slide to answer "what makes it an agent and not a script?" A script follows fixed steps. An agent can go back. There are four common kinds of loop. One: ask and retry, the one in our demo, when information is missing. Two: self-check, where the agent reviews its own draft and rewrites it. Three: human feedback, where a person's rejection sends the work back with a comment. Note that in our current demo the manager step is a branch, not a loop: a rejection ends the case. Four: tool retry, when a system fails. And always mention the stop rule: every loop has a limit and an exit to a person.
